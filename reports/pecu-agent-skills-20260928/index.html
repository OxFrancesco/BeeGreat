Pecu agent skills

Pecu's system prompt is now 3.2 KB instead of 14.3 KB. Everything task-specific moved into eight skills: wallet, Safe, Aerodrome and stocks, Aave, Polymarket odds, Polymarket accounts, Nansen and funding. Each skill owns its tools. A request only sees the skills its words call for, plus wallet address, balances, ask_user and load_skills.

On 17 scenarios covering every skill, time to the first real tool call dropped from 4.9 s to 2.3 s (median) and prompt tokens by 79%. Tool choice went from 46/51 to 50/51 correct.

How a request picks its skills

First, trigger words in the message ("swap", "Polymarket odds", "supply to Aave", a 0x address). If none match, the classifier's family when it is 90% sure. If still nothing, the previous turn's skills, so "Use this plan" after a liquidity suggestion goes straight to aero_liquidity. The model can load any other skill with load_skills; it shows up on the next step. enable_all_tools, which exposed all 139 tools and about 125 KB of schemas, is gone.

The old runtime lost most of its time there: 27 of 51 samples expanded the catalog, then ran a second step with far more tools. With skills, the only loads were the scenario built to need one ("Increase my Nvidia exposure", no trigger word). Odds (2.7 s vs 1.9 s) and Safe info (2.5 s vs 2.2 s) were slightly slower, within noise at 3 samples. The one skills miss read wallet_address next to the balance before a send, which the self-send rule allows but the strict rubric counts.

Verification

  • Pecu suite: 1,022 passed, 0 failed. Typecheck, lint, four Worker dry-run builds and the public docs build pass.
  • 339 command recipes parse: every parser verb, all 17 Aero SDK actions, all 52 Polymarket endpoints, every prefix.
  • Every one of the 139 registered tools belongs to exactly one skill or the base set. Routing fixture covers loading, carry-over across turns, explanation turns, both inference routes.
  • Not verified: live signed transactions and the deployed Worker. No funds moved.
